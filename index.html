assertEquals 是 JUnit 测试中常用的一个方法。它用于测试变量的实际值是否与其预期值相等。

当你创建 JUnit 测试文件时，你应该在每个测试方法前面都加上一个 @Test 注解，并且（在方法内部）可以有一个或多个 assertEquals 或 assertTrue 方法（这些方法由 JUnit 库提供）。

所有的测试（方法）都必须是非静态的 (non-static)。

这可能看起来有点奇怪，因为你的测试（方法）并不使用实例变量，而且你很可能也不会去实例化这个（测试）类。然而，JUnit 的设计者就是这样决定测试应该如何编写的，所以我们就照做好了。

References, Recursion, and Lists：

References (引用) 与 “盒子与指针” 模型

  • Java 变量的两种类型：

    1. 基本类型 (Primitives): int, double, boolean 等。变量盒子直接存储值。

      • int x = 5; (盒子 x 里装着 5)

    2. 引用类型 (References): 数组 (Arrays) 和对象 (Objects)。变量盒子存储的是地址（指针），指向内存中实际的对象。

      • IntList L = new IntList(5, null); (盒子 L 里装着一个箭头，指向新创建的 IntList 对象)

  • 赋值 (=) 的含义：

    • 对基本类型：复制值。

    • 对引用类型：复制地址（箭头）。两个变量将指向同一个对象。

      • IntList L2 = L; (现在 L2 也指向了 L 所指向的那个对象)

  • 参数传递 (Parameter Passing)：

    • Java 永远是 “按值传递” (Pass-by-value)。

    • 传基本类型：复制值，方法内修改不影响外部。

    • 传引用类型：复制地址，方法内可以通过该地址修改所指向的对象，但无法修改外部变量的指向。

Recursion (递归)

  • 递归三要素：

    1. Base Case (基本情况): 最小的、可以直接求解的问题（例如 null 链表或 size == 0）。这是递归的停止条件。

    2. Recursive Step (递归步骤): 如何将当前问题分解为更小的、同类子问题。

    3. Leap of Faith (信仰之跃): 假设递归调用 recursiveCall(smallerProblem) 能够正确解决那个更小的问题，然后利用它的结果来解决当前问题。

  • 递归 vs. 迭代 (Iteration)：

    • 几乎所有递归都能转为迭代，反之亦然。

    • 递归代码通常更简洁，(也更难)。

    • 迭代通常效率更高（节省函数调用栈的空间）。

Lists (链表)

  • IntList (本章核心数据结构):

    • 一个典型的递归定义的数据结构。

    • 一个 IntList 对象包含两部分：

      1. int first; (当前节点的值)

      2. IntList rest; (指向列表其余部分的引用，它本身也是一个 IntList)

    • 最后一个节点的 rest 为 null。

  • 两种处理 IntList 的方法：

    1. 迭代 (Iterative): 使用 while 循环和临时指针（如 p）遍历链表。

      • IntList p = L; while (p != null) { ...; p = p.rest; }

    2. 递归 (Recursive): 完美契合 IntList 的定义。

      • size(L) 的定义：

        • Base Case: if (L == null) return 0;

        • Recursive Step: return 1 + size(L.rest);

java是一个静态类型的语言，不具备有损的隐式转换的功能，定义为int类型时无法赋予5.3这样的值（c语言中则是可以赋值但是会导致精度丢失，也就是“隐式转换”）

特性 C 语言 Java 语言
int i = 3.14; 允许（编译通过） 不允许（编译错误）
转换方式 隐式转换（Implicit） 必须显式转换（Explicit Cast）
结果 自动截断小数，i 变为 3 必须写成 int i = (int)3.14;，i 才会变为 3
